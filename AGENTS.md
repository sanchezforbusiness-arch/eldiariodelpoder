# Project conventions

- Keep press entries and external audio metadata in `src/data/press.ts`; use its `pressPodcastSchema` helper in press and founder JSON-LD so audio interviews are never marked as news articles.
- Founder profiles accept optional social links so adding one founder's profile does not change another's links.
- Use `src/data/contact.ts` as the sole contact-email source so mailbox updates propagate to visible content, mailto links and structured data.
- Keep literal country editorial data in `src/data/countries.ts`; country loaders use `src/data/countryPage.ts` to share a stable schedule and FAQ snapshot between SSR, hydration and JSON-LD.
- Keep `/paises` as `paises.index.tsx` and country details as `paises.$slug.tsx` so each detail mounts independently, without an index layout swallowing it.
- Sitemap content sources must paginate public reads and return failure instead of partial XML; lastmod uses only page-specific content timestamps, never generation time.
- Sponsorship submissions use shared Zod validation in `src/data/sponsorship.ts`, a public server function with an insert-only client and a database rate-limit trigger; this keeps submissions private and validates both entry points.
- Render home copy and its FAQ schema from `src/i18n/landing.ts` through LandingContext, with Spanish defaults for shared chrome; HomeLanding owns the unchanged composition and insertion slots so future locales reuse it without duplicating layout. Keep podcast metadata canonical with optional dictionary overrides and only prefix links once translated destinations exist.
- Static English and Arabic landing routes use hand-authored dictionaries, shared leaf head metadata and reciprocal alternates; derive document language from the matched pathname during SSR and scope Arabic fonts and RTL overrides to that document language to preserve Spanish rendering.
- Country landings except Spain reuse HomeLanding with CountryBand and CountrySponsor; serialize their dictionary beside the existing country snapshot so schedules and FAQ remain identical in SSR, hydration and JSON-LD, while Spain retains its original template.
- Static language choices are real anchors; other languages use a one-use session marker when returning from a static edition to Spanish, so translation happens only after an explicit choice and never from browser preferences.
- Render the leadership guide FAQ from its shared route data so visible answers and JSON-LD remain identical; derive guide episode and country lists from the canonical data sources.
- Keep the club destination, identity and program data in `src/data/club.ts`; derive every external club URL through its exports so changing the domain requires one edit. HomeLanding includes its dictionary-driven club band immediately before the FAQ, alongside optional country content; Spain retains its separate template.
